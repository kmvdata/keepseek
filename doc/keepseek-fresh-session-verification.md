# 新建会话立即就绪：回归与现场验收

本轮基线为 `276eb3f9053410a4b497faa5c83d7398df80f279`、`package.json` 0.5.3，开始时工作树干净。修复目标是旧会话仍在加载时也能新建真正的空会话，并在新会话自身保存后立即就绪；不将所有历史或启动工作宣告为已完成。行为合同见 [交互生命周期](keepseek-interaction-lifecycle.md#新建空会话)。改动不提交、不发布、不提升版本。

## 实现与兼容

- 新建按钮消费独立 `canCreateSession`；历史仍消费 `canNavigate`。真正运行、待接受提交、保存及只读 owner 的限制保留。
- `ChatSessionStore.createFreshSession()` 在旧加载之外建立空 UUID、选择目标并增量提交其分片，不写旧占位会话。V2 分片路径不加载旧会话正文；新建不准备未使用的项目来源/Skills，不触发模型或标题请求。
- 新会话本地就绪允许编辑和接收发送准备；首次发送先取得 owner，完成真实安全存储、模型和自身上下文准备，再按原耐久 ACK 合同接收正文。失败保留草稿；旧批准、permit 和执行队列不复活。
- 旧加载/重载完成时保留新会话原内存对象及其消息、脏 revision 和选择；旧初始化错误、上下文结果和项目助手初始化不重定向当前普通会话。
- V2 分片与 workspace 索引沿用现有事务合并；新建保存前只读小型索引继承已存 ask/delegate 偏好，较新的明确模式选择优先，不打开旧活动正文。V1 旧内联数据沿现有迁移并与并发新建串行协调，不用局部新列表覆盖旧历史。没有新增持久化字段或 schema/request protocol 版本。

## F5 原生验收

空工程正常新建路径已有上述有限现场证据；以下完整矩阵仍有**待现场验证**项。重复验收使用隔离测试 workspace 和开发宿主独立用户/扩展存储；不要删除真实会话、改系统时钟或对用户工程运行副作用。deferred/故障注入的可重复入口是上述自动化测试；没有受控暂停能力时，原生只能记录所观察到的正常路径，不能据此声称迟到竞态已现场通过。

1. 在仓库运行 `bun run compile` 后按 F5 启动开发宿主，打开临时工程和 KeepSeek。分别准备空历史、长旧会话、旧 V1 导入 fixture。记录平台、HEAD、fixture 规模与新建点击/保存完成/输入可用时间；不记录正文或凭据。
2. 旧会话显示“加载会话”时点击顶部新建普通会话。预期只有自身必要保存可短暂显示“正在保存”，随后空正文立即就绪，可输入多行文本；旧正文仍加载不再使这个新目标显示“加载会话”。连续点击在同次保存中只产生一个新目标。
3. 不发送即可检查新建没有模型/标题请求。用受控 Provider 发送测试文本：应先显示准备任务，完成安全、模型及自身上下文后才持久接收；只在匹配 accepted 后清稿。缺失来源或注入准备错误时应显示真实错误并保留草稿，不能无限显示加载会话。
4. 在自动化暂停旧加载/旧 Skills 的同等 fixture 中释放旧成功及失败；核对新会话目标、草稿和新接受消息不变，项目助手稍后初始化不将它切回 Router。回到历史 A→B→A、复制历史会话，原安全恢复和选择保存仍生效。
5. 普通新建与窄栏“新任务 +”分别验收：前者是空白普通会话，后者仍是既有 Worker 新任务；项目助手入口仍打开 Router。新普通会话不继承旧任务 card/session/root，后台任务与原审批/Apply/Discard 目标不受影响。
6. 主任务实际运行时点击新建应受原互斥保护；owner/observer 双窗口中 observer 保持只读。检查 pending ACK、中文 IME、引用/@/Skills 草稿及设置入口，确认新建能力不绕过已有输入与操作边界。
7. 关闭重开及重启后核对新会话已存、旧会话仍可查看，V1/V2 历史未丢；重启仅恢复说明，不恢复批准/permit/执行队列。真实模型与副作用测试另行使用受控 transport/临时工程，不为取得证据调用付费模型。

保存与旧 V1 首次分片迁移所需真实磁盘 I/O 仍是新建的必要屏障；旧 V1 导入可能读取并保存其内联历史，以免新索引覆盖旧数据。故障应明确报错，不能用假就绪掩盖。历史选择仍等待其真实加载与恢复，本次没有取消这条保护。
