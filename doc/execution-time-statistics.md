# 用量统计执行时间 / Usage execution time

- **本次时间 / Current run time**：最近一个逻辑运行的 `usedMs`，恢复仍属于同一运行；结束后保留。不是发送消息后的自然时间。
- **会话累计时间 / Session total time**：当前会话中各根运行有效时间的总和，包含正在执行的运行；子运行不另行相加。
- 口径保持 `ExecutionClock` 不变：活跃 scope 的并集；等待授权、Apply、子代理等待释放本层 scope，真正活动的 child 使用共享父时钟。暂停和运行结束后不按自然时间继续增长；宿主阻塞期间的活跃时间仍计入。

`ChatSession.executionTime` v1 记录 taskId → 最大已见 usedMs。重复检查点、结束通知、恢复和 Epoch 切换只更新同一高水位，不重复累加。存储前及宿主检查点回调合并，沿用会话快照、顺序持久化与原子文件存储；传输只携带宿主计算结果。不会进入 Provider 请求，也不参与预算计算。

新会话从可靠零开始。旧会话由现存 checkpoint 或归档 summary 按 taskId 去重恢复；由于旧格式无法证明所有历史运行都仍在，不宣称完整，并显示“历史记录不完整 / History incomplete”。没有可靠运行值时显示未知，有部分值则显示可恢复部分。再次加载保持结果不变。损坏或非法数值不计入，标记不完整。未落盘即崩溃的活跃片段仍受原有检查点间隔限制（目前 15 秒），不通过墙钟猜补。

两项共用持续时长格式，毫秒保留，显示向下取整到秒：`HH:mm:ss`；跨天为 `D 天 HH:mm:ss` / `D day(s) HH:mm:ss`。沿用原有网格、主题色与等宽数字，无新 UI 计时器或磁盘写入定时器。

验证：新增回归覆盖宿主高水位、归档迁移与序列化、无效值、格式边界和活跃 scope 并集。真实 VS Code 的中英文、深浅主题、窄侧栏和运行状态交互仍需在加载新版扩展后人工验收；源码及离线测试不能代替该验收。
