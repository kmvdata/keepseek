# Markdown 列表渲染

## 问题与根因

2026-11-10 的用户反馈：原文有五个编号步骤，各步骤包含缩进子项，步骤间用空行分隔；聊天界面五个步骤均显示为 `1.`，但消息底部复制按钮取得的 Markdown 是正确的。

旧解析器有三个相互叠加的问题：

1. `parseMarkdownListItemLine()` 只返回有序/无序和正文，丢弃起始数字、标记和缩进信息。
2. `collectMarkdownList()` 遇空行即停止，同一列表被拆成多个只有一项的列表。
3. `appendMarkdownList()` 创建 `<ol>` 时没有设置 `start`，且只按行内语法渲染条目。浏览器对每个独立列表默认从 1 编号，子项的 `-` 则显示为普通字符。

`copyMessageText()` 直接读取 `message.content`，所以复制结果不受错误 DOM 影响。CSS 没有重置计数器；助手流式阶段显示纯文本，终态才执行 Markdown 渲染，因此不是消息排序或流式增量顺序错误。

## 当前行为与维护约束

- 保留列表的首项数字、标记类型、标记缩进和正文起始列。空格及 Tab 按列计算，Tab 使用四列停靠点；多位数字的标记也参与正文缩进计算。
- 同层、同类型、同标记的条目可以跨空行组成一个列表。标记前的轻微缩进变化如果未达到父项正文起始列，仍归为同级；达到正文缩进后才作为子块收集。未跨空行且仍在首段内的正文允许不足父项正文缩进的续行。空行后的未缩进独立段落、标题和分隔线结束列表。标记变化也建立新列表，禁止跨整个消息用全局计数器续号。
- 有序列表只给 `<ol>` 设置原文首项的 `start`，后续交给浏览器正常递增。不能逐个给 `<li>` 设置原文数字：源 Markdown 全部写成 `1.` 时仍应显示 1、2、3。
- 列表条目递归执行块级解析，支持已有的段落、子列表、围栏代码、表格等。精确去掉父项的正文缩进，保留更深层结构；围栏中的列表字符保持代码文本。
- 渲染深度到 64 层后将剩余正文作为文本显示，避免调用栈耗尽；保留外层后续条目。
- 条目内段落与子列表使用紧凑样式，多段正文保留段落间距。
- 这是现有安全 DOM 渲染器的局部修复，不增加第三方解析依赖，也不声明完整 CommonMark 支持。块内容沿用现有 `createElement`、文本节点和受控行内渲染，不把模型正文当成 HTML 注入。

消息内容、会话持久化、Provider 请求、缓存前缀、复制链路与 Webview 消息类型均不改变。历史消息在下次重绘时使用修复后的渲染器，无需修改历史数据或重新请求模型。用户消息、助手终态及历史加载使用同一渲染入口；流式阶段仍显示原始文本。

## 自动回归

`test/markdownRendering.test.ts` 已接入默认 runner。测试执行完整生成脚本、状态消息和 transcript 点击处理，覆盖：

1. 五步方案跨空行连续编号、每步嵌套子项；同时检查用户和助手消息。
2. 源标记全部为 `1.` 时自然递增；从 3 和 0 开始及独立段落后的新列表。
3. 有序/无序混合嵌套、多位数字正文缩进及嵌套列表的独立起始数字。
4. 条目内多段正文、围栏代码和表格；代码中的伪列表不变成列表结构。
5. 流式转终态与重新加载历史得到相同列表结构。
6. 点击消息复制按钮保留 CRLF 和尾换行的原始文本。
7. `.`/`)`、`-`/`+` 标记变化，以及标题/分隔线的列表边界。
8. Tab 缩进和空列表项。
9. 70 层嵌套受控降级，最深正文和外层后续条目均保留。
10. 同级条目缩进轻微变化及两空格正文续行不拆开列表，覆盖单/多位数字标记。

修复前新增测试的首批六条中五条失败、复制原文一条通过，复现五个独立 `<ol>`。该 DOM harness 不执行浏览器排版，不能代替原生 VS Code 现场验收。

2026-11-10 验证记录：`bun run compile`、`bun run lint`、`bun run build:test` 均通过；最终列表专项 10/10 通过。`bun run test` 全量运行记录为 1342 通过、0 失败、1 跳过；跳过项是环境不允许绑定本地端口的网络故障服务器测试。未完成原生 VS Code 界面验收。

## 原生验收

1. 用修复后的扩展执行 F5，或按正常流程安装本地构建并重载窗口。
2. 打开原有五步回复，确认序号为 1–5，每个步骤的子项嵌套在对应步骤内。切换会话后返回，再次检查。
3. 检查包含围栏代码、表格、非 1 起始序号及多层列表的回复；确认代码内容、缩进和滚动正常。
4. 点击消息底部复制按钮，确认 Markdown 原文与修复前一致。
5. 在深浅主题和窄面板检查编号、子项及代码块是否可见。现场结果单独记录，不由自动 DOM 回归推定通过。
